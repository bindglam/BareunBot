# 평가 보고서
## 1. 개요
 - 실시 일자: 10월 4일
 - 평가 대상 모델: `gemma-4-26B-A4B-it`
 - 평가 목적:
   - 기존 비속어 필터로 활용 중인 Gemma 4 모델의 탐지 성능 검증
   - 필터링 과정에서의 취약점 및 오탐/미탐 문제점 분석
   - 프롬프트 조건 변화에 따른 모델 응답 특성 파악

## 2. 평가 설계 및 구축
### 2.1 평가 방식
입력 문장(또는 텍스트) 내 비속어 포함 여부를 모델이 이진 분류(탐지/허가)하도록 설계했습니다. 전체 평가 셋 판별 후 정답 문항 수를 기준으로 모델의 탐지 성능을 정량 평가했습니다.

### 2.2 평가 데이터셋 구조
평가 데이터는 카테고리, 원문 내용, 검열 여부, 검열 사유로 구성된 JSON 포맷으로 정의했습니다.
```json
[
  {
    "category": "카테고리 영문명",
    “content“: "비속어 또는 바른말",
    "should_censored": true 또는 false,
    "reason": "검열 또는 허가 근거"
  },
  ...
]
```

### 2.3 데이터 구축 및 실험 환경
 - 데이터셋 구축: Gemini를 활용해 다양한 유형을 포함한 총 140개의 평가 데이터를 생성했습니다. (욕설/비속어뿐만 아니라 정치적 발언, 도배성 텍스트 등 포함)
 - 실험 조건:
   1. 조건 1 (단순 프롬프트): 최소한의 검열 요청 명령만 포함된 기본 프롬프트
   2. 조건 2 (구체적 프롬프트): 상세 검열 기준 및 세부 조건이 명시된 프롬프트

## 3. 평가 결과
| 구분 | 총 문항 수 | 오답 수 | 주요 오답 카테고리 | 비고 |
| ------ | ------ | ------ | ----- | ----- |
| 조건 1 (단순 프롬프트) | 140 | 2개 | 정치 (2개) | 1건 비정상 응답 발생 |
| 조건 2 (구체적 프롬프트) | 140 | 6개 | 정치 (3개), 기타 (3개) | 1건 비정상 응답 발생 |

 - 조건 1: 정치 카테고리에서 발생한 2문제를 제외하고 전 문항을 정확히 판별했습니다.
 - 조건 2: 정치 카테고리 3문제, 기타 카테고리 3문제로 총 6문제의 오답이 발생했습니다.
 - 공통 이슈: 두 조건 모두 특정 1개 데이터에 대해 올바른 판단을 내리지 못하고 비정상 응답을 반환했습니다.

## 4. 결과 분석 및 고찰
1. 전반적인 높은 정답률
   - 모델의 기본 언어 이해 능력 및 필터링 성능이 우수함을 시사하나, 동시에 생성된 140개의 평가 데이터 난이도가 다소 평이했을 가능성이 존재합니다.
2. 구체적 프롬프트 적용 시 오답 증가 원인
   - 조건을 상세히 부여했을 때 오답이 4개 더 증가하는 양상을 보였습니다.
   - 데이터셋에는 욕설 외에도 정치적 표현, 도배 등이 복합적으로 포함되어 있으나, 모델이 명시된 특정 조건에 과도하게 집중하면서 명시되지 않은 범주의 위반 사항을 놓치거나 오판한 것으로 분석됩니다.
3. 특정 데이터 비정상 응답 원인
   - 두 실험 모두 동일한 1개 문항에서 비정상적인 출력이 발생했습니다.
   - 해당 데이터의 입력 포맷 중 '글의 제목' 필드가 누락되어 문맥을 파악하지 못해 발생한 문제로 추정됩니다.

## 5. 결론 및 향후 계획
 - 평가 데이터셋 고도화: 단순 비속어 외에 우회 표현, 문맥 의존적 비속어, 은어 등 난이도가 높은 엣지 케이스(Edge case)를 보강할 예정입니다. 또한 참/거짓(이진 분류, Binary Classification) 모델의 성능 평가 척도를 조사하여 더욱 체계적인 분석 결과를 도출하도록 수정하겠습니다.
 - 프롬프트 가이드라인 재정비: 특정 조건에만 편향되지 않도록 복합적인 위반 유형(도배, 정치, 혐오 표현 등)을 균형 있게 포괄하는 프롬프트를 설계하겠습니다.
 - 입력 전처리 및 규격 표준화: 제목 및 본문 등 텍스트 구조 누락으로 인한 판별 오류를 방지하기 위해 입력 데이터 전처리 로직을 보완할 계획입니다.
